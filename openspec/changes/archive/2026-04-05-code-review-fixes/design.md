## Context

代码审查识别出以下需要改进的领域：

| 领域 | 当前状态 | 目标状态 |
|------|----------|----------|
| 依赖版本 | 25 个包过期 | 更新至最新稳定版 |
| 安全配置 | `0.0.0.0` 绑定警告 | 可配置绑定地址 |
| 异常处理 | 3 处静默 `pass` | 记录警告日志 |
| 代码格式 | 1 文件未格式化 | 100% 格式化 |
| GitNexus 索引 | 落后 102 提交 | 同步至最新 |

## Goals / Non-Goals

**Goals:**
- 更新过期依赖包并验证兼容性
- 修复安全扫描警告
- 标准化异常处理
- 保持测试覆盖率 80%+
- 刷新代码智能索引

**Non-Goals:**
- 大文件拆分（留作后续独立变更）
- DEPRECATED API 移除（需要迁移期）
- 功能性代码改动

## Decisions

### D1: 依赖更新策略

**选择**: 分批更新 + 测试验证

**理由**: 一次性更新 25 个包风险较高，分批可精确定位问题

**批次划分**:
1. **安全关键**: `sqlalchemy`, `anthropic`, `numpy`
2. **工具链**: `black`, `ruff`, `pytest-env`
3. **框架**: `langchain`, `langgraph`, `litellm`
4. **其他**: 剩余依赖

**替代方案**: 全量更新 — 风险高，难以定位问题

### D2: 绑定地址配置

**选择**: 环境变量控制 + 默认安全值

**实现**:
```python
# src/config/settings.py
host: str = os.getenv("HOST", "127.0.0.1")
```

**理由**: 保持向后兼容，同时允许生产环境覆盖

### D3: 异常处理标准化

**选择**: 添加结构化警告日志

**实现**:
```python
except Exception as exc:
    log.warning("operation_fallback", error=str(exc))
```

**理由**: 保持现有行为（降级/回退），但增加可观测性

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 依赖更新破坏兼容性 | 测试失败 | 分批更新，每批运行测试 |
| `127.0.0.1` 默认值影响部署 | 容器无法访问 | 文档说明需设置 `HOST=0.0.0.0` |
| 日志增加性能开销 | 轻微影响 | 使用结构化日志，异步写入 |
