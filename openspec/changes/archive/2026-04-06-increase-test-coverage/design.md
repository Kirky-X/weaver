## Context

当前测试覆盖率 83.16%，距离 85% 目标差 1.84 个百分点。通过分析覆盖率报告，识别出 5 个关键低覆盖率模块需要补充测试：

| 模块 | 当前覆盖率 | 主要缺失 |
|------|-----------|----------|
| `duckdb_handler.py` | 46.67% | 查询执行、连接管理、错误处理 |
| `spacy_extractor.py` | 67.01% | 实体提取分支、语言检测 |
| `metrics.py` | 76.40% | 边计算、社区检测度量 |
| `incremental_community_updater.py` | 77.76% | 增量更新流程、回滚场景 |
| `batch_merger.py` | 79.25% | 合并冲突、去重边缘情况 |

## Goals / Non-Goals

**Goals:**
- 将整体测试覆盖率从 83.16% 提升至 85%+
- 为 5 个低覆盖率模块补充缺失的测试用例
- 覆盖异常处理路径和边缘情况
- 确保所有测试通过且无新增警告

**Non-Goals:**
- 不修改生产代码逻辑
- 不改变现有 API 接口
- 不添加新的功能特性
- 不处理覆盖率超过 80% 的模块

## Decisions

### 1. 测试框架选择

**决策**: 使用现有 pytest + pytest-asyncio 框架，保持与项目一致。

**理由**:
- 项目已配置 pytest 生态（pytest-asyncio、pytest-cov）
- 无需引入新依赖
- 保持测试风格一致

### 2. 测试策略

**决策**: 采用分层测试策略

| 层级 | 覆盖范围 | 测试类型 |
|------|----------|----------|
| 单元测试 | 函数/方法级别 | 独立逻辑验证 |
| 集成测试 | 模块交互 | 数据库/API 集成 |

**理由**: 覆盖率报告基于单元测试，优先补充单元测试，必要时补充集成测试。

### 3. Mock 策略

**决策**:
- DuckDB 测试使用内存数据库
- Neo4j 测试使用 mock 连接
- 外部服务（SpaCy 模型）使用固定测试数据

**理由**: 避免外部依赖，确保测试可重复执行。

### 4. 测试优先级

**决策**: 按覆盖率差距从大到小排序

1. `duckdb_handler.py` (差距 38.33%)
2. `spacy_extractor.py` (差距 17.99%)
3. `metrics.py` (差距 8.60%)
4. `incremental_community_updater.py` (差距 7.24%)
5. `batch_merger.py` (差距 5.75%)

**理由**: 优先处理差距最大的模块，最小化工作量达成目标。

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| SpaCy 模型加载缓慢 | 测试执行时间增加 | 使用 `@pytest.fixture(scope="module")` 缓存模型 |
| DuckDB 内存数据库行为差异 | 测试可能无法捕获生产问题 | 添加集成测试验证真实数据库 |
| 覆盖率统计不准确 | 可能遗漏关键路径 | 使用 `--cov-report=term-missing` 定位缺失行 |
| 测试用例维护成本 | 长期维护负担 | 编写清晰的测试描述和注释 |
